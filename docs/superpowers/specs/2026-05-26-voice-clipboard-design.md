# Voice-to-Clipboard App Design

## Overview
A local-network service that allows the user to record voice via their smartphone's web browser, instantly transcribe the speech using Groq's high-speed Whisper API, and paste the resulting text directly into their laptop's clipboard. 

## Architecture
- **Backend (Laptop):** A Python server (using FastAPI or Flask) running locally. It serves the frontend assets, receives audio files via POST requests, interacts with the Groq API for transcription, and manages the laptop clipboard using `pyperclip`.
- **Frontend (Phone):** A lightweight HTML/JS web app styled for mobile. It uses the `MediaRecorder` API to capture audio from the phone's microphone.

## Components & Data Flow
1. **Access:** The user accesses the web app on their phone via `http://<laptop-ip>:<port>`.
2. **UI Controls:** 
   - A central microphone button with WhatsApp-style interaction:
     - **Hold:** Starts and continues recording.
     - **Slide Up:** Locks the recording for hands-free mode.
     - **Release/Stop Tap:** Ends the recording and triggers the upload.
   - A toggle setting: "Show transcriptions on phone".
3. **Transcription Pipeline:**
   - The phone POSTs the audio blob (WebM/Ogg format) to the `/transcribe` endpoint on the laptop.
   - The laptop sends the audio blob to the Groq API (`whisper-large-v3-turbo`).
   - Groq returns the text string.
4. **Output Action:**
   - The laptop uses `pyperclip` to inject the text into the system clipboard.
   - The laptop returns the text in the HTTP response to the phone.
   - If the "Show transcriptions" toggle is active on the phone, the transcribed text is displayed on the screen.

## Error Handling
- **Microphone Permissions:** If the browser denies access, display a clear warning prompt to the user.
- **Network/API Failures:** If the Groq API times out or errors, or if the phone loses connection to the laptop's hotspot, display a red failure notification on the phone so the user knows the clipboard wasn't updated.
- **Clipboard Compatibility:** The laptop environment requires clipboard drivers (e.g., `xclip` or `wl-clipboard` for Linux) for `pyperclip` to function correctly.

## API Keys
- The Groq API key is stored securely in an `.env` file on the laptop, never exposed to the frontend or hardcoded in the repository.

## Testing Strategy
- **Interaction Testing:** Verify the "hold-to-record" and "slide-to-lock" gestures behave naturally on touch devices.
- **Audio Format Testing:** Ensure the audio format generated by mobile browsers is natively compatible with Groq API requirements.
- **Clipboard Integration Testing:** Verify `pyperclip` functions reliably on the user's specific Linux desktop environment.
